# Правила значимости изменений

Сопоставляй записи по полному URL без сокращения, удаления параметров или нормализации адреса. Применяй эти правила к предыдущему и текущему массивам до перезаписи истории.

## Цены

Сравнивай `regular_price` и `sale_price` отдельно. Для двух достоверных чисел:

```text
percent_change = ((current_price - previous_price) / previous_price) * 100
```

Изменение значимо при `abs(percent_change) >= 1`. Изменение менее 1% сохрани в полном diff с `significant: false`, но не включай в итоговый список уведомлений. Равные значения не создают изменение. Не округляй процент перед проверкой порога.

Если предыдущая цена равна нулю, процент не рассчитывай (`percent_change: null`). Любое отличие от нуля значимо; `0 → 0` не создаёт изменение. Отрицательные цены, нечисловые значения и бесконечности являются ошибками данных.

`regular_price: null` означает отсутствие достоверной обычной цены. Переходы между `null` и числом сохраняй как диагностику доступности данных, без процента и без значимого ценового изменения.

## Скидка

- `sale_price: null → число`: `sale_appeared`, значимое изменение, процент `null`.
- `sale_price: число → null`: `sale_disappeared`, значимое изменение, процент `null`.
- Два разных числа: `sale_price_changed`, применяй порог 1% и правило предыдущего нуля.
- Два `null` не создают изменение.

Эти правила применяй только к двум успешным результатам; ошибка извлечения не означает исчезновение скидки.

## Рассрочка

- `has_credit: false → true`: `credit_appeared`, значимое изменение.
- `has_credit: true → false`: `credit_disappeared`, значимое изменение.
- Одинаковые значения не создают изменение.
- Процент не применим: `percent_change: null`.
- Не подставляй `false` вместо неизвестного значения. Успешная запись должна содержать булево значение; в ошибочном результате рассрочка неизвестна.

## Состав списка

- URL только в текущем массиве: `product_added`, значимое изменение состава.
- URL только в предыдущем массиве: `product_removed`, значимое изменение состава.
- Членство определяй по наличию URL, а не по статусу извлечения. Новый URL с ошибкой всё равно добавлен в отслеживаемый список; его ошибка отдельно остаётся диагностикой, а ценового изменения не возникает.
- Для изменения состава `field: "url"`, `old_value`/`new_value` — URL либо `null`; `percent_change: null`.

## Ошибки извлечения и восстановление

`extraction_failed` не означает, что товар исчез. При текущей ошибке для URL, присутствующего в обоих массивах:

- не сравнивай цены или `has_credit`;
- не создавай `product_removed`;
- сохрани статус и причину как диагностику;
- не включай ошибку в значимые ценовые изменения.

Если предыдущий результат ошибочный, а текущий успешный, зафиксируй `data_recovered` в диагностике. Не рассчитывай процент, не создавай изменения цены, скидки или рассрочки без достоверной прошлой записи и не объявляй товар новым.

## Формат и фильтрация

Каждое изменение содержит ровно `url`, `change_type`, `field`, `old_value`, `new_value`, `percent_change`, `significant`, `reason`. `reason` — короткое объяснение, `significant` — булево значение; цены и процент — числа либо `null`.

Полный `changes` содержит значимые и незначительные изменения. `significant_changes` содержит только элементы `changes` с `significant: true`; это список для будущих уведомлений. `diagnostics` хранит ошибки и восстановление отдельно. Уведомления Telegram на этом шаге не отправляй.

Допустимые типы значимых изменений: `regular_price_changed`, `sale_price_changed`, `sale_appeared`, `sale_disappeared`, `credit_appeared`, `credit_disappeared`, `product_added`, `product_removed`. В пользовательском отчёте показывай только `significant_changes`; полный diff остаётся во временных файлах. Диагностику показывай отдельно от изменений. Если значимых изменений нет, выводи точно: «Значимых изменений по сравнению с предыдущим прогоном нет.»

В первый запуск без предыдущего файла верни пустые `changes` и `significant_changes`; ошибки текущего извлечения всё равно сохрани в `diagnostics`. Нулевой список изменений — корректный результат.

## Контрольные примеры

| Предыдущее → текущее | Результат |
|---|---|
| Обычная цена 1000 → 1005 | 0.5%, незначимо |
| Обычная цена 1000 → 1010 | 1%, значимо |
| Обычная цена 1000 → 990 | −1%, значимо |
| Цена 0 → 100 | Процент `null`, значимо |
| Цена 0 → 0 | Нет изменения |
| Скидка `null` → 900 | Скидка появилась, значимо |
| Скидка 900 → `null` | Скидка исчезла, значимо |
| Рассрочка `false` → `true` | Рассрочка появилась, значимо |
| Успех → ошибка, URL сохранён | Только диагностика, товар не удалён |
| Ошибка → успех, URL сохранён | Восстановление данных, без ценового diff |
